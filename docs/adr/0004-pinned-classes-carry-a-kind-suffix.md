# Operation and fragment classes carry a kind suffix, and a clash with a shape name is an error

Operation, template and fragment classes bear the name the developer wrote, and the generator does not rename them; models, by contrast, take names by the rules of ADR 0001. In one module namespace this produced a silent move: a model held `Post`, a new operation `query Post` took the name, the model moved to `PostWithId`, and the existing `Post` import started meaning the operation class. So pinned classes carry a kind suffix: an operation and a template get `Query`, `Mutation` or `Subscription` (`GetUserQuery`, the template base `GetUserQueryBound`, the result root `GetUserQueryResult`), a fragment gets `Fragment` (`ImageUrlFragment`); no exceptions, `query GetUserQuery` gives `GetUserQueryQuery`. An anonymous operation gets the stem `anonymous` and the hash of its text whatever its kind — `Anonymous<hash>Query`, `Anonymous<hash>Mutation`, `Anonymous<hash>Subscription`: the kind is already named by the suffix, and the stem explains where the hash in the name comes from. The suffix does not make a clash unrepresentable — GraphQL and Python names are written in one alphabet, and a type `PostQuery` or a field `query` on `Post` again give a shared name — so a pinned name that matches any name claimed by a model or alias shape is a `GraphQLGenerationError` with a hint to rename the operation, template or fragment. Slot subtree models are pinned too, as are fragment subtree models and aliases: their names follow the path from the template or fragment, do not move, and a shape that merely stepped around such a name would take it the day the fragment or template is renamed. The suffix costs little: the consumer gets operation, template and fragment classes through `<module>_gql("…")`, not by import.

## Considered Options

- **Only an error, without a suffix** — no renames, but the error would fire on ordinary input such as `query Post` with a type `Post`. Rejected.
- **Only a suffix** — the silent move remains in rare clashes. Rejected.
- **Forbid an operation name that matches a schema type name** — independent of other queries, but does not catch clashes with short and detailed names. Rejected.
- **Narrow ADR 0001: a name the developer wrote is their explicit action** — loudness stays with basedpyright, and the import does not fail. Rejected.
- **An anonymous name stem by kind** (`Mutation<hash>Mutation`) or a shared `query<hash>` for every kind — the first repeats the kind word, the second calls a mutation and a subscription a query. Rejected.
